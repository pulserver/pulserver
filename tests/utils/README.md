# Test fixture data

## `expected/`

Checked-in ground-truth artifacts consumed by the C test suite
(`tests/ctests/`) and the C++ test suite (`tests/cpptests/`); their
CMakeLists point `*_FIXTURES_DIR` here. Contents per case:

- `<base>.seq` — the Pulseq sequence the tests load. Fixtures named
  `*_fail_*` or `*_corrupted` are deliberate negative-test inputs the
  readers must reject.
- `<base>.pge` / `<base>.pseg` — pulseg binary cache companions, produced
  by the `write_cache` CLI (`tests/cpptests/write_cache_cli`).
- `<base>_seq_desc.truth`, `<base>_meta.txt`, `<base>_*.bin` truth files —
  independent ground truth computed with the reference MATLAB Pulseq
  toolbox. Formats are documented in `SCHEMA.md`; the field-by-field
  readers live in `tests/ctests/test_seg_helpers.h` and
  `tests/cpptests/test_seq_desc_truth.cpp`.
- `MANIFEST.json` — per-case companion-file listing.
- `binary/` — paired text/binary fixtures for `test_pulseq_binary.c`,
  regenerated by `make_binary_fixtures.py` (see its module docstring).

The `expected/` artifacts are **frozen**: no in-repo generator exists, and
they must not be edited by hand. The pulseg cache/truth rework replaces
this corpus wholesale with fixtures generated from `pulserver.pypulseq`
and Python-computed truths; until then, treat the directory as read-only
input data.

## `expected_recon_dumps/`

Reference recon-cache dumps produced by
`tests/cpptests/dump_recon_cache.cpp` and compared by the recon C tests.

## `make_binary_fixtures.py`

Regenerates `expected/binary/`. Python-only; run from the repository root.

## `generate_fixtures.py`

Regenerates the `pulserver.pypulseq`-written corpus under
`tests/python/fixtures/` (entries defined in
`tests/python/fixture_corpus.py`). Run via
`bash scripts/regenerate_fixtures.sh`; the output is deterministic.
