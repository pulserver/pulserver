Scanner sequences#

A scanner sequence is a plugin file, <name>.py in a --plugins directory, defining one SequencePlugin subclass that binds a sequence function to the scanner protocol:

# sequences/gre.py
from pypulseqpp.sequences.sequence.gre2D_sequence import gre2d
from pulserver.design import SequencePlugin


class Gre(SequencePlugin):
    app = gre2d

The interpreter names it --plugin gre. Without protocol, the protocol is the sequence function’s defaults. A PyPulseq script becomes a sequence function by taking the scanner limits and its parameters as arguments and returning its sequence (from a PyPulseq script).

Protocol entries#

protocol maps the parameters of the interpreter’s table, the members of ProtocolKey, to entries; UIParam collects those of the UI controls. A plain string naming a parameter is stored as its member, and a name outside the table is refused when the class is defined. Each entry names the keyword argument of the sequence function it sets.

>>> from pypulseqpp.sequences.sequence.gre2D_sequence import gre2d
>>> from pulserver.design import (FloatParam, IntParam, SequencePlugin, TEPreset,
...                               TimeParam, TRPreset, UIParam)
>>> class Gre2D(SequencePlugin):
...     app = gre2d
...     protocol = {
...         UIParam.TE: TimeParam("te", range_min=1000, range_max=80000, range_incr=10,
...                         presets={TEPreset.MINIMUM: None}),
...         UIParam.TR: TimeParam("tr", range_min=1000, range_max=5_000_000,
...                         presets={TRPreset.MINIMUM: None}),
...         UIParam.FOV: FloatParam("fov_x", unit="mm", scale=1e-3,
...                           range_min=50.0, range_max=500.0),
...         UIParam.NX: IntParam("n_x", range_min=32, range_max=512, range_incr=2),
...     }

The options of the four string-list parameters are SequenceType, ImagingMode, PreparationType and TriggerType, which ChoiceParam takes as its choices: ChoiceParam("mode", ImagingMode). The argument receives the member, a str equal to the option.

A preset is a negative value the interpreter sends in place of a time. {TEPreset.MINIMUM: None} passes None, for which the sequence function designs its shortest echo time. An entry’s default replaces the sequence function’s default as the initial value, in UI units: default=TEPreset.MINIMUM offers an initial protocol that a scanner with weaker gradients than the function’s default assumes can play.

The class names no reconstruction: the reconstruction client, or the scan on a console, names it (Reconstruction plugins). A recon or follows attribute has no effect and raises a DeprecationWarning, as do ui and ScannerSequence, the deprecated names of protocol and SequencePlugin, and StringListParam().

Sequence functions#

A sequence function takes the scanner limits, a pypulseqpp.Opts, and one keyword argument for each entry of protocol, and returns the designed pypulseqpp.Sequence. A list of sequences is a chain, the prescans first and the main sequence last; each file names the next as its NextSequence definition. The initial value of an entry is the default of its argument in the signature, so a functools.partial() is a sequence function too. The default evaluation does not call the function; generate() calls it when the design is generated (Protocol evaluation).

>>> import numpy as np
>>> import pypulseqpp as pp
>>> def pulse_acquire(system, flip=90.0, tr=100e-3, averages=8):
...     seq = pp.Sequence(system)
...     rf = pp.make_block_pulse(np.deg2rad(flip), duration=1e-3, system=system)
...     adc = pp.make_adc(256, duration=10e-3, system=system)
...     for _ in range(averages):
...         seq.add_block(rf)
...         seq.add_block(adc)
...         seq.add_block(pp.make_delay(tr - 11e-3))
...     return seq
>>> class PulseAcquire(SequencePlugin):
...     app = pulse_acquire
...     protocol = {
...         UIParam.FLIP: FloatParam("flip", unit="deg", range_min=1.0, range_max=180.0),
...         UIParam.TR: TimeParam("tr", range_min=20000, range_max=5_000_000),
...         UIParam.NEX: IntParam("averages", range_min=1, range_max=64),
...     }
>>> listing = PulseAcquire().listing()
>>> {key.value: listing[key].value for key in PulseAcquire.protocol}
{'flip': 90.0, 'TR': 100000, 'nex': 8}

The last twelve entries are the prescription, which the interpreter fills from the scanner’s: the field-of-view offset, applied when the IR is built, and the rotation from the logical to the physical axes, in whose frame the design is checked (Protocol resolution). A plugin cannot bind them.

nex is the number of signal averages, listed by every plugin that does not declare its own (AveragesParam). The design plays its main sequence that many times, written into the block table once the sequence is designed, each repetition past the first numbered by AVG, and the scan time counts each. A plugin that binds nex to an argument of its sequence function, as PulseAcquire above does, plays its averages itself.

validate() evaluates a request under the scanner limits and returns the protocol the design plays. Entries the request omits keep their initial values. The default evaluation accepts the protocol unchanged, so the reply repeats the request, a preset included, and states no scan time:

>>> system = pp.Opts(max_grad=40, grad_unit="mT/m", max_slew=150, slew_unit="T/m/s")
>>> reply = Gre2D().validate(system, {"TE": TEPreset.MINIMUM, "nx": 96})
>>> reply.valid, reply.duration, reply.info
(True, None, '')
>>> reply.values["TE"] is TEPreset.MINIMUM, reply.values["nx"]
(True, 96)

An evaluation that designs the sequence states the values the design achieved. The TE and TR definitions of a pypulseqpp sequence record its echo time and repetition time, and pypulseqpp.sequences.duration() sums the durations of the sequences of a chain:

>>> from pypulseqpp import sequences
>>> from pulserver.design import Evaluation
>>> class Resolved(Gre2D):
...     def evaluate(self, system, protocol):
...         seq = self.app(system, **protocol.arguments)
...         achieved = {UIParam.TE: seq.definitions["TE"][0],
...                     UIParam.TR: seq.definitions["TR"][0]}
...         return Evaluation(protocol.replace(achieved), sequences.duration(seq))
>>> reply = Resolved().validate(system, {"TE": TEPreset.MINIMUM, "nx": 96})
>>> reply.valid, round(reply.duration, 3), reply.info
(True, 38.25, '')
>>> {name: reply.values[name] for name in ("TE", "TR", "fov", "nx")}
{'TE': 3080, 'TR': 250000, 'fov': 220.0, 'nx': 96}

The resolved TE is the shortest echo time of the design in place of the preset. Values are rounded to the precision a scanner parameter stores, so a resolved protocol sent back resolves to itself. A protocol the evaluation rejects is invalid, and the message of the error it raised is the reply’s info:

>>> reply = Resolved().validate(system, {"TE": 1000})
>>> reply.valid, reply.info
(False, 'the requested TE of 1.000 ms is shorter than the 3.400 ms this readout can achieve')

duration is the scan time in seconds. An evaluation that states a duration of 0.0 states no estimate: the protocol is valid, duration is None, and the reply reports the scan time as unknown.

design() generates the design and writes it as signed binary Pulseq, prescans first, and returns the written paths. The first file is sequence.seq, and each file names the next as its NextSequence definition. The generate design call then converts the design to the IR cache and stores it (Architecture).

Protocol evaluation#

A plugin overrides evaluate() to check a protocol and to state what the console shows with it. The hook takes the scanner limits and the requested Protocol, in the units of the sequence function’s arguments, and returns an Evaluation: the protocol holding the values the design achieves, the scan time in seconds, a note shown with the valid protocol and, optionally, the RF layout (RF layout). Returning None accepts the protocol unchanged. Raising an exception makes the protocol invalid:

>>> class Timed(PulseAcquire):
...     def evaluate(self, system, protocol):
...         if protocol[UIParam.TR] < 12e-3:
...             raise ValueError("the TR is shorter than the pulse and the readout")
...         scan_time = protocol[UIParam.NEX] * protocol[UIParam.TR]
...         return Evaluation(protocol, scan_time, "256 samples per average")
>>> reply = Timed().validate(system, {"TR": 50000, "nex": 4})
>>> reply.valid, reply.duration, reply.info
(True, 0.2, '256 samples per average')
>>> reply = Timed().validate(system, {"TR": 10000})
>>> reply.valid, reply.info
(False, 'the TR is shorter than the pulse and the readout')

The default evaluation does not call the sequence function, so a protocol the function cannot realize is found only when the sequence is generated, as an error of that call, and not while the operator edits the protocol. An evaluate that builds or checks the design rejects such a protocol when it is evaluated.

ValueError and AssertionError, which pypulseqpp and PyPulseq raise for an event or a timing they cannot realize, reject the protocol with the message of the error as info, and are logged as a warning. Any other exception also makes the protocol invalid, but the reply names only its type, as in TypeError in Timed.evaluate, and the exception is logged as an error with its traceback. A request that names an entry the protocol does not declare, or an option a choice does not offer, is invalid in the same way.

generate() builds the sequence of a requested protocol. The default calls the sequence function with the arguments of the protocol; a plugin overrides it to return a sequence, or a list of them, built another way. validate and design are not overridden: they are the boundary between a request and the code of a plugin, and design writes nothing for an invalid request.

Exam cache#

An evaluate or generate that declares an exam argument receives the directory of the current exam’s cache, which the design calls take as --exam, and reads what the exam’s reconstructions stored there, such as b0_map, b1_map or coil_sensitivities, with load_exam(). Without an exam the argument is not passed:

from pulserver.design import Evaluation, SequencePlugin, load_exam


class Shimmed(SequencePlugin):
    app = pulse_acquire

    def evaluate(self, system, protocol, exam=None):
        if exam is None:
            return Evaluation(protocol, 0.0, "no B0 map")
        b0_map = load_exam(exam)["b0_map"]
        return Evaluation(protocol, 0.0, f"B0 map {tuple(b0_map.shape)}")

A key no reconstruction stored raises KeyError. The values are those of the series that measured them, on their own grid. For such a plugin the files of the exam’s cache are part of the design’s identity, so a new map yields a new design.

RF layout#

An evaluation may state the RF its protocol plays, from which a scanner estimates the RF of a prescription before the design is generated. The layout is one TR: the RF instances that TR plays, with the TR as its period. RfLayout.of takes the RF instances of a sequence that is one TR, as pypulseqpp.Sequence.rf_instances() returns them, and the control each instance’s amplitude follows: the flip angle, UIParam.FLIP, or a float user entry, UIParam.user_value(n), either declared in protocol. One control applies to every instance; a list gives one per instance in play order, None for an instance no entry scales. The scanner multiplies the amplitude of an instance by the ratio of the value of its control in the protocol it plays to the value in the evaluated protocol. The period is the TR in seconds, and the duration of the sequence where omitted:

>>> from pulserver.design import RfLayout
>>> from pulserver.protocol import format_rf_layout
>>> class Costed(PulseAcquire):
...     def evaluate(self, system, protocol):
...         one_tr = pulse_acquire(system, **(protocol.arguments | {"averages": 1}))
...         layout = RfLayout.of(one_tr, UIParam.FLIP)
...         scan_time = protocol[UIParam.NEX] * protocol[UIParam.TR]
...         return Evaluation(protocol, scan_time, rf_layout=layout)
>>> reply = Costed().validate(system, {"nex": 4})
>>> print(format_rf_layout(reply.rf_layout), end="")
[RfLayout]
period 0.1
run 0 1 flip 1
[RfLayout End]

A sequence shorter than the TR, such as one TR without its closing delay, is stated with the TR: RfLayout.of(seq, UIParam.FLIP, period=tr).

The layout is optional. An evaluation that states none is valid and states no estimate; one whose control is not an entry of protocol, or has no positive value in the evaluated protocol, is invalid. What the scanner checks before the scan is the stored design, not the layout. The blocks that carry the layout are described in Protocol resolution.

RF phase convention#

Phases and frequencies keep Pulseq’s units: an RF phase shape holds cycles, RF and ADC phase offsets and RF shim phases are in radians, and frequency offsets are in hertz. The ppm offsets are resolved to hertz and radians at the scanner’s Larmor frequency when the IR is built.

An RF waveform \(b_c(t)\) and an RF shim weight \(w_c\) are the complex drive of transmit channel \(c\), the envelope of a carrier \(e^{+i\omega_0 t}\). Protons precess clockwise about the static field, and the part of the field that turns them is the conjugate of the drive times the channel’s transmit sensitivity \(s^+_c\), the rotating field of a unit drive:

\[ b^+(\mathbf{r}, t) = \sum_c \overline{w_c\, b_c(t)}\; s^+_c(\mathbf{r}). \]

A drive of phase \(+\phi\), on one channel through its shim weight or its waveform, or on every channel through the pulse’s phase offset, turns the excited magnetization and the reconstructed image by \(-\phi\); an ADC phase offset of \(+\theta\) turns them by \(+\theta\), so a receiver that follows the pulse’s phase offset cancels it. A pulse of phase zero tips \(+z\) towards \(+y\). On the scanner, a channel driven at \(+\phi\) relative to another appears at \(-\phi\) in the reconstructed images, for RF shims and per-channel waveforms alike. The virtual scanner follows the same convention, and the VOP check takes the drives as they are written: the SAR of a pulse is \(v^H Q\, v\) for \(v_c = d\, w_c\, b_c(t)\), with \(d\) the drive per hertz of RF amplitude.

A per-channel image of a small-angle excitation has the phase of \(s^+_c\) plus the receive phase and a constant. A shim fitted to such maps under the model \(\sum_c w_c\, s^+_c\) is written as \(\overline{w_c}\).

Options#

Choices that set what a sequence is, rather than a value an operator tunes from scan to scan, are options: module constants a plugin declares with option() at module level, before its class, so that they shape its sequence function and the protocol it declares. Each option is a user entry: the plugin lists it in user<n>_value as the index of its value among its choices, 0 or 1 for a flag, and names it and the code of each choice in user<n>_name. A design call loads the plugin at the options its request holds in those entries, and list at those of the value block it is given, so a protocol carries its options as it carries every other entry. A console lists the plugin again when an option entry changes. An option shows or hides user entries; it never gives one another meaning.

from pulserver.design import Description, FloatParam, SequencePlugin, UIParam, option

VARIABLE_DENSITY = option("variable_density", False, user=42, label="Variable density")


class Spiral(SequencePlugin):
    app = spiral
    protocol = {...}
    if VARIABLE_DENSITY:
        protocol |= {
            UIParam.user_name(12): Description("Periphery undersampling"),
            UIParam.user_value(12): FloatParam("undersampling", range_min=1.0),
        }

An option that is not a flag names its choices, at most five. A request whose option entry holds no index of a choice is refused, and so is one stating an entry its options hide. The options join the design’s identity and its manifest.

Diffusion tables#

A diffusion sequence plays a table of b-values and directions read from a file, as a scanner’s own diffusion sequences do: the console names the table by number in the UIParam.DIFFUSION_TABLE entry, with the largest b-value in UIParam.DIFFUSION_BVALUES and the number of directions in UIParam.DIFFUSION_DIRECTIONS; the sequence function turns the number into the file’s path with module constants a site sets, reads the file and records its path with pypulseqpp.io.set_diffusion_table(). The proxy reads the same file again, so the table reaches the reconstruction without being copied into the sequence (Reconstruction plugins).

import os

import pypulseqpp as pp
from pulserver.design import FloatParam, IntParam, SequencePlugin, UIParam

TENSOR_DIRECTORY = "/data/diffusion"
TENSOR_PREFIX = "tensor"
TENSOR_SUFFIX = ".dat"


def dwi(system, table=1, b_value=1000.0, directions=30):
    seq = pp.Sequence(system)
    name = f"{TENSOR_PREFIX}{table}{TENSOR_SUFFIX}"
    path = os.path.join(TENSOR_DIRECTORY, name)
    b, g = pp.io.set_diffusion_table(seq, path, b_value, directions)
    for volume, (b_volume, direction) in enumerate(zip(b, g)):
        ...  # one volume, its REP label set to `volume`
    return seq


class Dwi(SequencePlugin):
    app = dwi
    protocol = {
        UIParam.DIFFUSION_TABLE: IntParam("table", range_min=1),
        UIParam.DIFFUSION_BVALUES: FloatParam("b_value", unit="s/mm²"),
        UIParam.DIFFUSION_DIRECTIONS: IntParam("directions", range_min=1),
    }

The table is in the frame of the gradient channels, so its directions turn with the prescription.

Protocol conventions#

  • A 3D sequence takes its number of partitions from the number of slices.

  • Ry undersamples the phase encode of the Cartesian sequences, the blades of gre_propeller2d, se_propeller2d and the stacks of blades, and the shells of zte3d; Rz undersamples the partition encode of the 3D Cartesian ones.

  • The ETL of se_epi_propeller2d is its blade width.

  • The MPRAGE sequences take their inversion time as prep_time.

Shipped evaluation#

Each shipped plugin evaluates a protocol from one repetition of the scan: one line, partition, spoke, interleaf, blade line, echo train or inversion shot of one slice, without dummy repetitions. Most call the sequence function with the arguments that reduce it to that repetition; epi3d and zte3d build the repetition from the modules their function is built from.

  • Scan time. The duration of the repetition times the number of repetitions the prescription plays, with the slices that share a TR counted in the packets the sequence plays them in, plus the dummy repetitions: those of user0, or, at −1, the count pypulseqpp.sequences.steady_state_dummies() gives for that TR and flip angle.

  • Resolved values. Those the main sequence states for the prescription, where the plugin has the entry: the echo time and repetition time in its TE and TR definitions, the receiver bandwidth as the inverse of the dwell time of its first ADC event, and the slice thickness in its SliceThickness definition. A multi-echo sequence lists every echo time, and the TE entry holds the first.

  • Invalid protocols. A prescription the design refuses is invalid, with the message of its error.

  • RF layout. The first TR of the repetition, its shot repeated once per slice of the largest packet, with the TR as its period; for the balanced steady state, the TR after the half-angle pulse. The TR of a fast spin echo holds an echo train, that of an MPRAGE an inversion shot, and that of epi3d a volume. The flip angle is the control of every excitation of the plugins with a flip entry, which an MPRAGE’s inversion is not. The spin-echo plugins, fse3d among them, have none, and the amplitude of their excitation and refocusing pulses is that of the design.

Logging#

A plugin logs with the standard logging module, under a logger of its own (logging.getLogger(__name__)). Under a warm design server, what a call logs, prints or warns, and why it refuses a protocol, is appended to the file the request names under log, or else to the server’s standard error (Services).
